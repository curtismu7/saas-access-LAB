# Safety

- Loopback bind only (`SALAB_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1` only (a test pins it). The container runs as a non-root user, read-only, with every capability dropped.
- Host header must be a loopback name; writes must be same-origin.
- Netguard blocks every outbound connection (fetch, socket, DNS, UDP) with a self-test, and a test asserts zero attempts in the server process across the whole API in both modes. There is no worker thread and no child process. Notifications to Slack, Mattermost, Teams, Jira and ServiceNow are rows in an in-memory outbox; the platform "API calls" are descriptions on `.example` hosts. Nothing is sent.
- **The lab holds no credential for any platform.** It names each platform's auth method (the deck's list: a personal access token, an administrator token, an OAuth JWT bearer with a connected app, key-pair authentication, an OAuth service principal, a service account with domain-wide delegation) and nothing more. There is no field that takes a credential: a body with an unknown key is refused (without naming the key), and the simulated platform call shows `never shown, never stored`.
- **Credential-shaped values the visitor types are masked, and the lab says it is a heuristic.** Free text (a reason, a comment) is cleaned on the way in: zero-width, soft-hyphen and bidi characters are deleted (so a token cannot be hidden by interleaving them), other control characters become spaces, credential-shaped runs are masked, and only then is the text cut to length (so a token that straddles the cut is masked, not half shown). The detectors are lab-written and linear: GitHub, GitLab, Slack, AWS, Google and OpenAI-style tokens (including short ones), JWTs, private-key blocks, `Bearer` and `Basic` values, `token <word>` with a digit, URL passwords (`scheme://user:pass@`), `password`, `pw`, `pass`, `secret key`, `account key` and `session id` followed by `:`, `=` or `is`, a four-word passphrase, and key-like runs of 20 characters or more. Not every secret has a recognisable shape: a short random password with no keyword before it is not found, so the page says not to type a real one. The raw value never enters state. Every JSON answer is masked again by the specific detectors as defence in depth. Error messages are fixed text and never include input; the first hop pane shows the route pattern, never the path; field names are not echoed; the final 404 and error handlers answer fixed JSON for every method and path (Express's default `Cannot POST /<path>` would echo a token typed into a URL); a workspace id that looks like a credential is refused rather than echoed. A test types every credential shape into every field of every endpoint (including the path, query, headers and unknown key names) and searches every answer, the state afterwards and the process output for it, and another sweeps every method over token-shaped paths with and without the web build.
- **Refusals as data.** The page sends `refusalsAs200: true` with every write. It changes one thing: an engine refusal (self-approval, an expired request, a bad duration) comes back as HTTP 200 with `ok: false` and the error code, because a browser logs every 4xx as a console error and a refusal the visitor asked for is the point of the demo. The Host check, same-origin writes, `bad_mode`, `unknown_field`, a malformed body, the body size limit and every Mock write (409) stay real 4xx errors; a cross-origin form cannot use the flag (same-origin writes are enforced first); answers are `no-store`. The page treats a write as a success only when the body says `ok: true`; a 200 without it is shown as a refusal.
- Every value used as an object key (platform, resource, level, policy id, vertical, scenario) is checked with `Object.hasOwn` and a type test; an unknown vertical or scenario falls back, an unknown platform, resource or policy is refused.
- Every grant carries an expiry. A request needs a whole number of minutes from 1 to the policy maximum (itself at most 10080); a string, negative, zero, fractional, NaN or missing duration is refused, and the grant itself refuses to exist without a bounded expiry. The lab clock only moves forward, at most 7 days per move.
- Input is bounded: bodies 32 KB, a reason 300 characters, a comment 200, 200 requests, 200 grants, 500 audit entries, 300 outbox entries, 400 platform entries, 40 hops per answer, 100 findings; a full workspace refuses new work with a clear code (Reset) instead of dropping anything silently. Workspaces are capped in count (500) and age (1 hour).
- The server writes no file (a test greps for write calls). The one home-directory touch is reading the optional shared settings file (`~/Development/.env`, or `STANDALONE_ENV`) with `util.parseEnv`, taking only `SAL_LAB_MODE`: no other key enters the server's environment. A bare `MODE` in it is ignored.
- Only `.example` and `.invalid` hosts appear in any shipped text (a doctor check scans the filled story in every vertical). The people, agents, repositories and roles are synthetic.
- Every product claim is labelled "Ping release claim, UNVERIFIED on our tenant" in the banner of every tab, in presenter mode too. Field names from the console swagger of 2026-10-31 are schema only; the lab says so wherever they appear, and tags each field as a swagger name, a lab reading or lab-invented.
